Abstract :

Hermes.io is an autonomous, full-stack educational intelligence platform designed to address the fragmentation, static rigidity, and lack of verified progression in modern self-directed technical education. Built upon a unified Node.js serverless HTTP micro-engine and backed by a dual-tier cloud database architecture utilizing Supabase PostgreSQL with resilient local file failover, Hermes synthesizes personalized, role-specific curriculum trees utilizing modern Large Language Model (LLM) inference. The platform incorporates multi-tiered learning modalities, offering both a custom 4-step wizard and a rich gallery of standardized industry blueprints. Each generated curriculum features an interactive, recursive milestone constellation with on-demand submodule expansions, verified knowledge mastery quizzes, and an executive Hermes Overseer Terminal secured via stateless cryptographic HMAC-SHA256 tokens. Interactive features include procedural celestial planet avatars, a cosmic living universe canvas with slow-falling shooting stars, and a tactile Slide to Enter gateway. Rigorous automated verification demonstrates sub-15ms telemetry latency, seamless offline fallback, and high-fidelity progress synchronization across distributed serverless environments.

1. Introduction

1.1 Purpose

The purpose of the Hermes.io project is to engineer an enterprise-grade, end-to-end learning path synthesizer and tracking dashboard. Self-directed technical learners frequently confront unstructured tutorials, disjointed documentation, and open-ended roadmaps that lack actionable milestones, practical project callouts, or verifiable assessments. Hermes.io solves this paradigm by automatically transforming high-level career goals (e.g., Full Stack Developer, AI/ML Engineer, DevOps Architect) into interactive, multi-stage milestone constellations accompanied by automated exams, study hour rollups, and administrative telemetry.

1.2 Problem Statement

Current educational paradigms exhibit several critical bottlenecks:

  • Disjointed learning materials — Learners waste substantial time navigating heterogeneous blog posts, outdated documentation, and uncurated video playlists without clear prerequisites.
  • Static, non-adaptive curricula — Existing roadmap platforms offer static PNG/SVG diagrams that cannot dynamically adjust to a learner's prior experience or specific tech-stack preferences.
  • Absence of verified mastery — Traditional roadmaps rely entirely on self-reported checkboxes without evaluating comprehension through targeted conceptual assessments.
  • Administrative blind spots — Institutional supervisors and enterprise team leads lack real-time observability into team skill progression, milestone bottlenecks, and examination pass rates.

1.3 Objectives

To resolve the aforementioned challenges, Hermes.io fulfills the following engineering objectives:

  1. Design a responsive, cosmic-themed web interface featuring a tactile Slide to Enter gate, live universe background with slow shooting stars, and procedural SVG celestial star/planet avatars.
  2. Implement an intelligent roadmap synthesis pipeline leveraging Gemini generative AI with graceful local fallback heuristics for fully offline continuity.
  3. Provide on-demand, recursive submodule expansion enabling learners to drill deep into complex technical milestones without losing overall curriculum context.
  4. Develop a verified examination engine supporting multi-question modular mastery quizzes with score analytics and badge rewards.
  5. Construct the Hermes Overseer Terminal, an enterprise telemetry console powered by stateless HMAC-SHA256 authentication for serverless environments.
  6. Implement cloud persistence using Supabase PostgreSQL with automated schema migration, row-level security (RLS), and zero-loss local JSON synchronization.

2. Tools and Technologies

2.1 Frontend Architecture

The frontend interface is engineered using semantic HTML5, modern CSS3 design tokens, and modular, vanilla JavaScript (ESNext). By avoiding bloated component frameworks, Hermes achieves instant first-contentful-paint (FCP), zero build-step overhead, and smooth 60fps animations. Key components include:

  • Phosphor Icons Web (v2.1.1) — Comprehensive iconography across regular and fill states.
  • Google Fonts — Plus Jakarta Sans for headings and UI copy; JetBrains Mono for telemetry, tokens, and monospace codes.
  • Celestial Avatars Engine — Deterministic procedural SVG generator producing 10 unique planetary and star archetypes seeded by user email addresses.

2.2 Backend & API Layer

The backend is powered by native Node.js without heavyweight external middleware dependencies.

  • Stateless HTTP Server — Lightweight RESTful micro-engine handling CORS, streaming JSON bodies, static asset caching, and security headers.
  • Stateless Cryptographic HMAC-SHA256 Auth — Replaces fragile in-memory serverless session stores with signed, self-contained bearer tokens (hadmin.<payload>.<signature>) that remain fully valid across dynamic Vercel Lambda container spin-ups.

2.3 Cloud Database & Resilience Layer

  • Supabase PostgreSQL (v15) — Cloud relational database managing persistent tables for users, sessions, roadmaps, quiz_results, and app_config.
  • Local JSON Failover — Autonomous filesystem persistence layer (data/users.json, data/roadmaps.json, data/quiz_results.json) guaranteeing 100% functional continuity during cloud outages or zero-configuration development.

2.4 AI Inference & Cloud Infrastructure

  • Google Gemini API (Gemini 2.5 Flash) — High-speed JSON schema generation for curriculum structuring, milestone sequencing, and contextual quiz formulation.
  • Vercel Serverless Edge — Continuous deployment pipeline with automated Git push triggering.

4. Implementation

4.1 Cosmic Splash Page with Tactile Slide Gateway

The entry experience features a full-viewport, zero-dependency cosmic splash page. The interface displays an astronomical planetary core with rotating dashed orbital rings, a slow shooting star particle animation, and the subtitle powered by thanatosvz.

To deliver an engaging tactile entry mechanic, a physics-inspired Slide to Enter slider is implemented. The user drags a glowing celestial thumb across an obsidian pill track. As dragging progresses, the label opacity dynamically diminishes. Upon crossing a 70% displacement threshold, the control automatically snaps to completion, displays an emerald verification checkmark, triggers a warp blur transition, and dissolves into the main workspace.

4.2 AI Curriculum Synthesizer & Submodule Engine

The curriculum synthesis engine connects to Google Gemini via secure serverless proxies. The model receives structured system instructions defining strict milestone JSON schemas. Each milestone node specifies:

  • title and description — Concise conceptual summaries.
  • estimatedHours — Quantitative workload estimates.
  • recommendationType — Core vs. recommended vs. optional.
  • projectCallout — Hands-on practical challenge.
  • resources — Free curated documentation and verified tutorials.

Learners can click any node to invoke the submodule expansion engine, prompting the AI to unpack abstract milestones into concrete sub-tasks.

4.3 Stateless HMAC-SHA256 Overseer Security Architecture

Traditional stateful in-memory sessions fail in serverless cloud environments (e.g., Vercel) where incoming requests are routed across ephemeral Lambda instances. Hermes resolves this using cryptographic HMAC-SHA256 tokens:

Token = "hadmin." + Base64Url(Payload) + "." + HMAC-SHA256(Base64Url(Payload), K_secret)

Every serverless instance cryptographically verifies token integrity and expiration without querying shared database memory, completely eliminating 401 session-loss anomalies.

4.4 Automated Examination Engine

Each curriculum milestone links directly to an automated knowledge verification modal. The system evaluates answers, aggregates percentage scores, stores completion timestamps, and renders color-coded mastery pills (Mastered ≥ 80%, Passed ≥ 60%, Review Required < 60%).

7.2 Bug Fix and Refactoring Log

  • Vercel Serverless Session Loss — Symptom: Admin dashboard returned 401 Unauthorized after navigating across pages on Vercel. Root Cause: Memory Map was partitioned across serverless lambdas. Fix: Replaced with stateless HMAC-SHA256 signature tokens.
  • Gate Error Flashing on Initial Load — Symptom: "Access Denied" error was visible before credentials were typed. Root Cause: Conflicting display: none and display: flex in inline styles. Fix: Enforced CSS class hierarchy with clean input listeners.
  • AI Loading Overlay Layout Inversion — Symptom: Status copy rendered awkwardly beneath animated GIF. Fix: Reordered flex column layout so pulsating status text renders directly above the GIF with a 2-second minimum duration.
